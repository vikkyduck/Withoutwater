# Архитектура — withoutwater.ru

**Версия 2 · 15 июля 2026** — актуализирована под боевой стек (Vite-SPA «Expert Compass»).
Версия 1 (14.07) описывала отменённый вариант статического HTML — заменён при репаковке.

Сквозной файл для нейросети и разработчика: к нему возвращаемся при каждой доработке.
Бизнес-контекст (что продаём, «чего у нас НЕТ», аудитория, доказательства) — в `brief.md`.
Юр. детали — в `legal-map.md`. Оперативная памятка для Claude — в `CLAUDE.md`.

---

## 1. Продукт

Лендинг агентства «Без Воды» (проектная команда методологов и продактов): посетитель
оставляет заявку на бесплатную диагностику → бэкенд пишет её в базу в РФ → шлёт
уведомление в Telegram → владелец обрабатывает заявку в админке.

Чем сайт **НЕ** является: не CRM, не личный кабинет, не магазин, не каталог тренеров.
Одна цель — заявка на созвон. Подробнее «чего у нас НЕТ» — `brief.md` §1.

## 2. Пользователи и приоритет устройства

- **Посетитель (главный, MVP).** Холодный/тёплый B2B-трафик (руководители обучения, HR,
  T&D в РФ). Действие ровно одно — **оставить заявку**. Никакой регистрации/аккаунта.
- **Владелец-администратор.** Виктория Уткина. Читает заявки в `/admin`, меняет статусы,
  экспортирует CSV, удаляет записи (исполнение запросов на удаление ПД).
- **Кого в MVP нет:** менеджеров с отдельными ролями, клиентских кабинетов, CRM-интеграции.

**Приоритет — mobile-first.** Аудитория приходит с телефона (после выступления/по
рекомендации), поэтому вёрстка проектируется от мобильного экрана вверх; десктоп —
расширение. Админка тоже адаптивна: открывается с телефона по TG-уведомлению.

## 3. Главный сценарий (поток заявки)

```
Форма (имя + канал связи + компания? + комментарий? + 2 чекбокса согласий + honeypot)
  → POST /api/lead → валидация → SQLite на VDS (РФ)          [ПД остаются в РФ]
  → JSONL-журнал (резерв, append-only)
  → Telegram @BV_Vikky_bot: «Новая заявка №N — открыть админку»   [БЕЗ ПД]
  → владелец открывает /admin → статус new → work → done
  → хранение 5 лет с последнего контакта (или до отзыва согласия)
  → отзыв согласия (письмо на vikavika.utkina@yandex.ru) → удаление записи в админке
```

CRM в контуре нет (по брифу). Появится — интегрируем после первичной записи в РФ.

## 4. Стек (актуальный)

- **Фронтенд:** Vite 6 + React 19 + Tailwind CSS v4 (`@tailwindcss/vite`, `@theme inline`) +
  `motion` (framer) + `lucide-react`. Дизайн «Expert Compass». Вся страница — один
  компонент `lovable/src/landing.tsx`. Тёмные секции, «жидкое стекло», тумблер «Тише
  анимации» (reduced-motion). Сборка статики: `npm run build` → `lovable/dist/`.
- **Шрифты — локально** (woff2 на сервере, не Google CDN: запрос к зарубежному CDN = передача
  IP за рубеж): **Unbounded** (заголовки) + **Manrope** (текст), кириллица+латиница.
- **Бэкенд:** zero-dependency Node ≥ 22.5 (`node:sqlite`), `backend/server.mjs`. Слушает
  `127.0.0.1:5020`, за nginx. Honeypot + rate-limit (20 заявок/час с IP). systemd
  `withoutwater-api`.
- **База:** SQLite `/opt/withoutwater/data/leads.db` (WAL, вне webroot). JSONL-журнал —
  резервный. См. §6.
- **Админка:** `/admin` за basic-auth (`ADMIN_USER`/`ADMIN_PASS`), `backend/admin.html` +
  `/admin/api/*`. Таблица заявок, статусы в один клик, поиск, CSV-экспорт, удаление.
- **Веб-сервер:** nginx — статика `lovable/dist` + прокси `/api/` и `/admin` на `:5020`,
  security-заголовки (HSTS, X-Content-Type-Options, X-Frame-Options).
- **Хостинг:** Timeweb VDS `5.129.198.180`, HTTPS Let's Encrypt (автопродление).

## 6. Модель данных

Одна сущность — **Заявка** (`leads`). Связей нет (аккаунтов/CRM нет). SQLite, `server.mjs`:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER PK | номер заявки (идёт в TG-уведомление) |
| `ts` | TEXT ISO | время создания |
| `name` | TEXT | имя (обращение) |
| `contact` | TEXT | телефон / Telegram / e-mail |
| `company` | TEXT | компания (необязательно) |
| `comment` | TEXT | суть задачи (необязательно) |
| `page` | TEXT | страница-источник |
| `ip`, `ua` | TEXT | IP и user-agent (антифрод/аудит) |
| `consent_pd_version` | TEXT | версия текста согласия на ПД (аудит 152-ФЗ) |
| `consent_pd_ts` | TEXT | время согласия на ПД |
| `consent_ads` | INTEGER | согласие на рекламную рассылку (0/1) |
| `consent_ads_ts` | TEXT | время рекламного согласия |
| `status` | TEXT | `new` → `work` → `done` |
| `legacy_fields` | TEXT | сырые поля старых Tilda-заявок (переходный период) |

Масштабируемость: раздельные поля согласий с версией и меткой времени (не «галочка была»,
а «на какой текст и когда»); миграция истории из JSONL под маркер-файлом (не повторяется).

## 7. API-контракт

Фронт (`landing.tsx`, форма) ↔ бэкенд (`server.mjs`). Всё JSON, origin ограничен CORS.

**`POST /api/lead`** — приём заявки. Тело:
```jsonc
{
  "name": "Имя",
  "contact": "+7… / @tg / e-mail",   // обязателен name ИЛИ contact
  "company": "…",                     // необязательно
  "comment": "…",                     // необязательно
  "consent_pd": true,                 // обязателен true, иначе 400 no_consent
  "consent_pd_version": "1.0-2026-07-14",
  "consent_ads": false,               // отдельное необязательное согласие
  "page": "/",
  "website": ""                       // honeypot: непусто → тихий 200, без записи
}
```
Ответы: `200 {ok:true, id}` · `400 {ok:false, error:"no_contact"|"no_consent"|"bad_body"}` ·
`413 too_large` · `429 {error:"rate_limited"}`.

**`GET /api/health`** → `{ok, tg, leads, admin}` (булевы: настроен ли TG, число заявок, настроена ли админка).

**Админка (basic-auth):**
- `GET /admin` → HTML-интерфейс
- `GET /admin/api/leads?status=&q=` → `{ok, leads[], counts}`
- `POST /admin/api/leads/:id/status` body `{status}` → `{ok}`
- `DELETE /admin/api/leads/:id` → `{ok}` (запрос на удаление ПД)
- `GET /admin/api/export.csv` → CSV (`;`-разделитель, BOM для Excel)

`/politics_pd` (политика), `/consent_pd` (согласие), `/pub_oferta` (оферта) — статические

## 11. Бэкапы

Cron на VDS: ежедневная копия `leads.db` в `/opt/withoutwater/backups/` (ротация 30 копий,
та же страна — требование локализации). Плюс снапшот VDS Timeweb, если включён.

## 12. Деплой

`./deploy.sh`: `npm run build` (в `lovable/`) → rsync `lovable/dist/` и `backend/` (без
`.env`) на VDS → `systemctl restart withoutwater-api` → health-check + проверка HTTPS.
DNS и сертификат уже работают — не трогаем. Секреты — только в `/opt/withoutwater/.env`
(`chmod 600`), в репозиторий не попадают.

## Страна хостинга

**Россия** (152-ФЗ: аудитория и первичная база заявок обязаны быть в РФ). Timeweb VDS,
nginx, HTTPS, systemd — всё в одном контуре. Ничего не переезжает.
